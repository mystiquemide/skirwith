MergePay Live proof Setup Safety GitHub
GitHub Action · Testnet

Pay maintainer-approved contributors after a genuinely merged pull request.

MergePay turns a trusted merged PR into a deterministic, policy-controlled stablecoin payout through KeeperHub on Ethereum Sepolia — with replay suppression, no automatic rebroadcast, and refusal before any broadcast.

Set it up See the live acceptance repo

How it works

Trusted merged PR→ Fresh GitHub state + default-branch config→ Deterministic policy→ Signed durable reservation→ KeeperHub simulation→ Exact-body broadcast once→ Receipt comment + explorer proof

Recipient and amount come only from maintainer-controlled mappings. Contributor text, code, and head-branch config are never trusted.

Set it up

  1. Add the trusted config .github/mergepay.yml on the default branch.
  2. Add a workflow that runs on pull_request: [closed] and uses the action.
  3. Set repo secrets KEEPERHUB_API_KEY and MERGE_PAY_RECEIPT_SECRET. The GitHub API token is automatic; no PAT is required.
  4. Merge an approved PR to trigger a payout.
# .github/mergepay.yml (default branch, trusted)
version: 1
repository: owner/name
chain:
  id: 11155111
  explorer: https://sepolia.etherscan.io
  token:
    address: "0x1c7d4b196cb0c7b01d743fbc6116a902379c7238"
    symbol: USDC
    decimals: 6
payout:
  requiredLabel: mergepay-approved
  maximum: "25"
  amounts:
    mergepay-5: "5"
recipients:
  contributor-login: "0x…"
checks:
  required: false
  names: []
# .github/workflows/settle.yml
on:
  pull_request:
    types: [closed]
permissions:
  contents: read
  checks: read
  pull-requests: write
concurrency:
  group: mergepay-${{ github.event.pull_request.number }}
  cancel-in-progress: false
jobs:
  settle:
    if: github.event.pull_request.merged == true
    runs-on: ubuntu-latest
    steps:
      - uses: mystiquemide/mergepay@<release-sha>
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          KEEPERHUB_API_KEY: ${{ secrets.KEEPERHUB_API_KEY }}
          MERGE_PAY_RECEIPT_SECRET: ${{ secrets.MERGE_PAY_RECEIPT_SECRET }}

The workflow never checks out or executes PR code. The action fetches trusted state and configuration through the GitHub API and only ever reads maintainer-controlled mappings for payment decisions.

Safety design

  • Recipient and amount resolve only from the trusted config; contributor content is untrusted.
  • A signed, durable reservation is written before any broadcast; no broadcast happens without it.
  • Simulation and broadcast use the exact same transfer parameters; any mismatch aborts.
  • Replays resolve the existing receipt and never broadcast a second transaction.
  • Uncertain outcomes become manual review with the execution id preserved — never an automatic rebroadcast.
  • Receipt markers are HMAC-authenticated with a dedicated key, so forged comments cannot suppress a payout.
MergePay is a testnet proof-of-concept for the KeeperHub Agents Onchain hackathon. No production or mainnet claim is made. See github.com/mystiquemide/mergepay.
