Skirwith

Pay approved contributors after a verified merge. Once.

Skirwith is a deterministic policy settlement agent delivered as a GitHub Action. It pays an approved contributor after a merged pull request (PR) through KeeperHub on Ethereum Sepolia. Repository policy controls the recipient and amount. A replay returns the existing proof instead of sending another payment. A refused run stops before any broadcast.

How it works

02Fresh GitHub state

04Signed reservation

06One broadcast
07Receipt comment

The workflow triggers on a closed PR. The action reads fresh state from GitHub. It reads the trusted config from the default branch. Policy picks the recipient and the amount from the config. The action writes a signed reservation before any broadcast. KeeperHub simulates the transfer, then broadcasts it once. The action posts a receipt comment with the explorer link.

Safety design
  • Recipient and amount come only from the trusted config. Contributor content is untrusted.
  • The action writes a signed reservation before any broadcast. It never broadcasts without a reservation.
  • Simulation and broadcast use the same transfer parameters. A mismatch aborts the run.
  • Replays resolve the existing receipt. They never broadcast a second transaction.
  • Uncertain outcomes become manual review. The action keeps the execution id. It never rebroadcasts.
  • Live evidence is Sepolia testnet evidence using controlled self-payments to the organization wallet.
  • Receipt markers use an HMAC (Hash-based Message Authentication Code) signature with a dedicated key. A forged comment cannot suppress a payout.
Set it up

Prerequisites

  • A repository that you control.
  • A KeeperHub organization API key. Create it at app.keeperhub.com.
  • A receipt signing secret. Generate a unique, high-entropy string and store it as SKIRWITH_RECEIPT_SECRET.

Steps

  1. Add the config file .github/skirwith.yml to the default branch.
  2. Add the workflow file .github/workflows/settle.yml.
  3. Set the repository secrets KEEPERHUB_API_KEY and SKIRWITH_RECEIPT_SECRET.
  4. Open a PR and add the labels that the config requires.
  5. Merge the PR.

You do not need a personal access token (PAT). GitHub Actions provides the GITHUB_TOKEN automatically. 

# .github/skirwith.yml (default branch, trusted)
version: 1
repository: owner/name
chain:
  id: 11155111
  explorer: https://sepolia.etherscan.io
  token:
    address: "0x1c7d4b196cb0c7b01d743fbc6116a902379c7238"
    symbol: USDC
    decimals: 6
payout:
  requiredLabel: skirwith-approved
  maximum: "25"
  amounts:
    skirwith-5: "5"
recipients:
  contributor-login: "0x…"
checks:
  required: false
  names: []
# .github/workflows/settle.yml
on:
  pull_request:
    types: [closed]
permissions:
  contents: read
  checks: read
  pull-requests: write
concurrency:
  group: skirwith-${{ github.event.pull_request.number }}
  cancel-in-progress: false
jobs:
  settle:
    if: github.event.pull_request.merged == true
    runs-on: ubuntu-latest
    steps:
      - uses: mystiquemide/skirwith@dc705c96e5ff098edbaa9e42c19437cd2d2c8fc6
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          KEEPERHUB_API_KEY: ${{ secrets.KEEPERHUB_API_KEY }}
          SKIRWITH_RECEIPT_SECRET: ${{ secrets.SKIRWITH_RECEIPT_SECRET }}

Expected result

The action runs after the merge. If policy passes, the wallet is funded, and KeeperHub is available, it broadcasts once and posts a receipt comment on the PR. The comment shows the transaction hash and the explorer link for the Sepolia transaction.

If the run does not settle

A blocked policy, a pending or manual-review outcome, missing secrets, or an unfunded testnet wallet all stop the action before any broadcast. Check the run log for the reason code, confirm the required label and recipient mapping, then review Configuration and the troubleshooting section. A run that reaches manual review never rebroadcasts; a maintainer resolves it from the recorded execution id.
